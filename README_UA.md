# ESP32: WebSocket-сервер та автоматична сигналізація мікроклімату

Автор: Григор’єв Георгій Артемович, М-КІ-52.
Проєкт для симуляції у Wokwi через Visual Studio Code. Мова C++, Arduino Core.

## 1. Що встановити на новому комп’ютері

1. Visual Studio Code: https://code.visualstudio.com/
2. У VS Code відкрийте Extensions (Ctrl+Shift+X) та встановіть:
   - PlatformIO IDE — ідентифікатор platformio.platformio-ide;
   - Wokwi Simulator — ідентифікатор wokwi.wokwi-vscode.
3. Дочекайтеся завершення початкового налаштування PlatformIO. Перезапустіть VS Code, якщо він цього попросить.
4. Активуйте ліцензію Wokwi на новому комп’ютері: F1 → Wokwi: Request a new License. У браузері ввійдіть до свого облікового запису з Hobby+ і підтвердьте повернення ліцензії до VS Code. Перевірте чинність своєї підписки.

PlatformIO Core входить до PlatformIO IDE. Окремий Arduino IDE, Live Server, Node.js та зовнішній сервер для запуску цього проєкту не потрібні. Бібліотеки встановлює PlatformIO за platformio.ini, а не менеджер розширень VS Code. WiFi, Wire, Arduino та FreeRTOS входять до платформи.

## 2. Файли

- platformio.ini — плата, платформа та залежності.
- diagram.json — повна схема Wokwi.
- wokwi.toml — шляхи прошивки та перенаправлення мережевого порту.
- src/main.cpp — прошивка, датчик, OLED, сервер та черга команд.
- include/alarm_logic.h — початкові межі та логіка порівняння.
- include/web_page.h — HTML/CSS/JavaScript вебінтерфейсу, який віддає ESP32.
- .vscode/extensions.json — рекомендовані розширення.

Файли мають бути збережені в UTF-8. Не вставляйте #include до platformio.ini.

## 3. Запуск

1. Розпакуйте архів, наприклад у C:\Projects\ESP32_Climate_Alarm.
2. У VS Code: File → Open Folder → виберіть саме папку з platformio.ini.
3. У PlatformIO виберіть Project Tasks → esp32dev → General → Build або натисніть Ctrl+Alt+B.
4. Перше збирання завантажить платформу й бібліотеки, тому потрібен доступ до інтернету. Дочекайтеся SUCCESS.
5. Натисніть F1 → Wokwi: Start Simulator. Використовуйте Private IoT Gateway для доступу до сервера ESP32. Шлюз входить до Wokwi for VS Code; окремий gateway.exe для цієї конфігурації не потрібен.
6. Дочекайтеся повідомлення в послідовному виводі симулятора: HTTP + WebSocket ready: http://localhost:8180/.
7. Відкрийте http://localhost:8180/ у браузері. Залиште симуляцію запущеною. Перші дані очікуються приблизно через 2 секунди часу симуляції.

Використовуйте Build, а потім Wokwi Start Simulator. Upload призначений для фізичної плати й тут не потрібний. Вивід віртуального ESP32 дивіться в консолі Wokwi; вибирати фізичний COM-порт не потрібно.

## 4. Підключення

| Пристрій | Контакт | ESP32 |
|---|---|---|
| DHT22 | VCC | 3V3 |
| DHT22 | SDA/DATA | GPIO15 |
| DHT22 | GND | GND |
| SSD1306 | VCC | 3V3 |
| SSD1306 | SDA | GPIO21 |
| SSD1306 | SCL | GPIO22 |
| SSD1306 | GND | GND |
| Світлодіод | Анод | GPIO18 через резистор 330 Ом |
| Світлодіод | Катод | GND |

Адреса OLED: 0x3C. На дисплеї постійно відображаються ПІБ, група й назва проєкту.

## 5. Логіка

Початковий допустимий діапазон: 18–30 °C та 30–70 % вологості. Це демонстраційні межі, не універсальні санітарні нормативи.

- Якщо T < Tmin АБО T > Tmax АБО H < Hmin АБО H > Hmax — червоний світлодіод світиться.
- Якщо обидва показники у межах — світлодіод вимкнений.
- Значення, рівне межі, вважається нормальним.
- Некоректне зчитування DHT22 — світлодіод блимає, браузер показує помилку датчика.
- До першого зчитування світлодіод вимкнений.
- Перевірка виконується раз на 2000 мс часу ESP32. Налаштована сигналізація працює і без відкритого браузера.

Немає ручної кнопки вимкнення тривоги: стан LED визначають показники. Двосторонній WebSocket-обмін збережено: браузер надсилає нові межі, ESP32 перевіряє їх, застосовує та повертає підтвердження і стан.

Межі редагуються у вебінтерфейсі. Температурні межі дозволено задавати в діапазоні -40…80 °C, вологість — 0…100 %. Мінімум повинен бути меншим за максимум. Налаштування зберігаються в оперативній пам’яті до перезапуску ESP32. Щоб змінити стартові значення назавжди, відредагуйте Limits у include/alarm_logic.h та зберіть прошивку знову.

Гістерезис у цій версії не використовується: після повернення обох показників у заданий діапазон тривога знімається під час наступного зчитування.

## 6. Демонстрація

Натисніть DHT22 у вікні Wokwi та задайте значення:

| Температура | Вологість | Очікувана поведінка |
|---|---|---|
| 24 °C | 40 % | LED вимкнений |
| 35 °C | 40 % | LED горить, висока температура |
| 15 °C | 40 % | LED горить, низька температура |
| 24 °C | 80 % | LED горить, висока вологість |
| 24 °C | 20 % | LED горить, низька вологість |
| 15 °C | 80 % | LED горить, дві причини одночасно |
| 18 °C | 30 % | LED вимкнений: рівність нижнім межам |
| 30 °C | 70 % | LED вимкнений: рівність верхнім межам |

Для перевірки зворотного обміну задайте на датчику 24 °C / 40 %, змініть у браузері максимальну температуру на 23 °C і натисніть «Застосувати на ESP32». Після підтвердження LED має загорітися. Поверніть максимум 30 °C — має згаснути.

Для перевірки втрати зв’язку залиште сторінку відкритою та зупиніть симуляцію. Після закриття сокета або приблизно 10 секунд без повідомлень сторінка очищує показники й повідомляє про відсутність зв’язку. При активній вкладці перевірка виконується кожні 500 мс. Фонові вкладки браузер може сповільнювати. Після повернення на вкладку виконується додаткова перевірка. Після перезапуску симуляції браузер повторює підключення автоматично. Перезавантажити саму вебсторінку, коли симуляція зупинена, неможливо: її HTTP-сервер також зупинений.

## 7. Якщо виникли проблеми

- Помилка AsyncTCP.h: перевірте, що відкрито корінь проєкту й використовується доданий platformio.ini. Залежність має власника ESP32Async.
- Не використовуйте застарілі дублікати ESPAsyncWebServer у папці lib. У чистому проєкті їх немає.
- Якщо бібліотека не завантажується, перевірте мережу, проксі та повідомлення PlatformIO. Помилка завантаження і помилка компіляції — різні причини.
- firmware.bin не знайдено: спочатку успішно виконайте Build.
- localhost:8180 недоступний: перевірте запуск симуляції, Wi-Fi, приватний шлюз та відсутність іншого сервера на порту 8180.
- Після зміни прошивки зупиніть симуляцію, виконайте Build і запустіть її знову; оновіть сторінку Ctrl+F5.
- Дуже повільна симуляція може спричинити повідомлення про застарілі дані навіть за відкритого з’єднання. TIMEOUT у include/web_page.h заданий у мілісекундах реального часу браузера.

## 8. Перевірки під час підготовки

Окремими автоматизованими перевірками перевірено C++-логіку всіх чотирьох меж, рівність межам, одночасні відхилення та некоректні налаштування. JavaScript перевірено на синтаксис; у моделі браузерного оточення перевірено отримання показників, тривогу, надсилання меж, підтвердження, мовчазну втрату зв’язку, перепідключення та помилку датчика.
Ці перевірки не замінюють збирання прошивки ESP32 та запуск у Wokwi. Фізична плата не використовувалася.
